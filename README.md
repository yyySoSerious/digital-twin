# Digital Twin

A conversational digital twin that answers questions about an engineer's
professional background, skills, and projects. It uses a Gradio chat interface,
OpenAI's Responses API and file search, and a document-backed knowledge base.

The assistant can also record contact details in PostgreSQL and send Pushover
notifications for contact requests and unanswered questions.

**Try the app:** [Open Digital Twin](https://huggingface.co/spaces/yyySoSerious/digital_twin)

## Features

- Chat about professional experience, projects, and technical skills.
- Search uploaded documents for relevant information and display cited filenames.
- Suggest starter questions in the chat interface.
- Record contact details and notify the owner when someone requests follow-up.
- Notify the owner when a question cannot be answered.

Responses are generated by an AI model and may be inaccurate. Review answers and
the source documents before relying on them.

## Requirements

- Python 3.12 or newer.
- [uv](https://docs.astral.sh/uv/) for the setup commands below.
- An OpenAI API key with access to the configured model and file search.
- A PostgreSQL database accessible from the application.
- A Pushover account and application token for notifications.

OpenAI API calls, file storage, and other services may incur charges.

## Setup

Run the following commands from the repository root.

### 1. Install dependencies

```bash
uv sync
```

### 2. Configure environment variables

Create a `.env` file in the repository root with your own values:

```dotenv
OPENAI_API_KEY=your_openai_api_key
DATABASE_URL=postgresql://user:password@localhost:5432/digital_twin
VECTOR_STORE_ID=your_vector_store_id
PUSHOVER_USER_KEY=your_pushover_user_key
PUSHOVER_TOKEN_KEY=your_pushover_application_token
```

Create the PostgreSQL database separately and ensure its user can create tables.
The app connects to it at startup and creates a `users` table if needed. The
Pushover values are needed for notification tools to work; those tools make
outbound requests when invoked.

If you don't have a vector store yet, leave `VECTOR_STORE_ID` as a placeholder
until the next step. Keep `.env` private: it is excluded by `.gitignore`.

### 3. Create the knowledge base

Place documents you want the assistant to use directly in `src/knowledge_base/`.
Use documents you have permission to upload and share. The setup script scans
files in that directory, uploads them to OpenAI, and creates a new vector store:

```bash
uv run python src/digital_twin/vector_store_setup.py
```

Check that each upload reports `completed`, then copy the printed vector store ID
into `VECTOR_STORE_ID` in `.env`. The script creates a **new** vector store on
every run; rerunning it does not update the existing store. Update the environment
variable if you create another store.

For GitHub projects, a concise Markdown file per project works well: include the
repository URL, purpose, technologies, your contributions, and relevant results.
The setup script does not automatically sync changes from GitHub.

### 4. Start the app

```bash
uv run python src/digital_twin/app.py
```

Open the local URL printed by Gradio. Ask a question or select a suggested prompt.
The application currently waits for a complete model response before displaying it.

## How it works

1. Gradio sends the user's message and chat history to `chat`.
2. The Responses API uses the system prompt and may search the configured vector
   store for relevant information.
3. If the model requests a function, the app executes it and sends the result
   back to the model.
4. The app displays the response and any cited filenames.

The system prompt asks the assistant not to invent information and to record
unanswered questions. File search is model-driven, so not every response
necessarily includes a source.

## Privacy and deployment

- Do not commit API keys, database credentials, `.env`, or generated application
  data. Review documents and prompts for personal or confidential information
  before committing them or uploading them to OpenAI.
- Chat messages and history are sent to OpenAI. Contact details are stored in
  PostgreSQL and may be sent to Pushover. Protect these services and handle
  collected information appropriately.
- The app has no configured authentication. Add appropriate access controls
  before exposing it publicly.

## Troubleshooting

- **App fails during startup:** Check `DATABASE_URL`, database connectivity, and
  permission to create tables. The database is initialized when tools are imported.
- **File search is not working:** Confirm `VECTOR_STORE_ID` points to the store
  containing your successfully indexed files and that the API key has access.
- **Notifications are not delivered:** Check the Pushover credentials and
  inspect the application logs for the notification response.
- **Model request fails:** Check the OpenAI API key, account access, and the
  configured `MODEL_NAME` in `app.py`.
